# 3단계 — C1~C4 제어 시나리오와 시간 재생

이 문서는 3단계의 로컬 합성 모델 설명입니다. 이후 추가한 FastAPI 연결과 현재 실행 방법은 [STEP4_GUIDE.md](STEP4_GUIDE.md)를 참고하세요.

이번 단계의 목표는 **같은 오염원 입력에 서로 다른 제어 정책을 적용하고 결과를 3D에서 확인하는 것**입니다. 이전 단계의 돈사 구조와 히트맵 위에 상태 관리·시간 모델·비교 그래프를 추가했습니다. 아직 실제 비전 AI, 학습 예측 모델, FastAPI, 실물 장치는 연결하지 않았습니다.

## 먼저 화면에서 확인하기

기존 http://127.0.0.1:4173/ 탭을 새로고침합니다. 소스를 수정했다면 프로젝트 폴더에서 `npm.cmd run build` 후 새로고침하세요. 서버가 꺼져 있으면 `npm.cmd run preview`도 실행합니다.

1. C3에서 시간을 11분으로 이동합니다. 팬이 HIGH(85%, 표시 RPM 1530)로 전환됩니다.
2. C2를 선택하면 시간이 0으로 초기화됩니다. 11분에는 기본 환기(30%, 540 RPM), 41분에는 HIGH입니다.
3. C1을 120분으로 이동하면 팬은 OFF이고 실내 지수는 1.110입니다. 색은 1 이상에서 빨강으로 포화됩니다.
4. C4의 11분에서는 팬과 스크러버가 함께 가동됩니다. 동일 시각의 실내 지수는 C3와 같습니다.
5. 재생 속도를 바꾸고 재생/일시정지를 누릅니다. 시간 이동은 자동으로 일시정지하며, 실험 초기화는 현재 시나리오의 0분으로 돌아갑니다. 시점 초기화는 카메라만 바꿉니다.

기본 환기는 C2~C4의 공통 조건입니다. 현실적인 상시 환기를 표현하기 위해 C2의 ‘뒤늦게 가동’을 기본 환기에서 고출력으로의 전환으로 구현했습니다. 완전 OFF인 조건은 C1입니다.

## 데이터가 화면까지 이동하는 흐름

`config.js → simulation.js → App.jsx → heatmapData.js → HeatmapFloor.jsx / Barn.jsx`

```jsx
const runs = useMemo(() =>
  Object.fromEntries(SCENARIOS.map(s => [s.id, simulateScenario(s.id)])), []);
const run = runs[scenario];
const frame = frameAt(run, time);
const values = useMemo(() => createScenarioGrid(frame.current), [frame.current]);
```

`simulateScenario`는 시나리오별 결과를 미리 계산합니다. `frameAt`은 선택한 시각의 상태를 꺼냅니다. `useMemo`는 해당 입력이 달라질 때만 결과를 다시 생성합니다. 되감기를 해도 이전 실행 상태가 섞이지 않고 같은 시각에는 같은 결과가 나타납니다. 실행 중 config 값을 편집했다면 페이지를 새로고침해 다시 계산하세요.

`frame.current`는 현재 실내 상대 농도 지수, `frame.predicted`는 현재 정보로 계산한 미래 지수입니다. 팬 상태는 `frame.pwm`, `frame.rpm`, 세정기는 `frame.scrubberOn`으로 표현됩니다. `Barn`은 이 상태에 따라 팬 날개를 돌리고 펌프 색상을 바꿉니다. 표시용 팬 회전은 감속되어 있으며 정지 화면에서는 애니메이션도 멈춥니다.

## 농도 변화 모델 이해하기

이번 모델의 가정은 `dC/dt = S - kC`입니다. C는 ppm이 아닌 실내 상대 지수, S는 분당 발생 지수, k는 분당 환기 제거계수입니다. 실내를 하나의 혼합 공간으로 보는 단순 모델이며 공간 CFD를 계산하지 않습니다.

```js
export function integrateIndex(current, source, k, minutes) {
  return k === 0 ? current + source * minutes
    : current * Math.exp(-k * minutes)
      + source / k * (1 - Math.exp(-k * minutes));
}
```

환기가 없으면 발생량만큼 지수가 증가합니다. 환기가 있으면 발생과 제거가 동시에 작용합니다. 이 함수는 해당 시간 구간에서 S와 k가 일정하다는 가정의 해석해를 사용합니다. 제어 판단은 기본 1분마다 수행합니다. 건물 부피와 실제 풍량을 이용한 보정은 없으므로 현재 BARN 치수를 바꿔도 이 농도 모델의 제거계수는 자동으로 바뀌지 않습니다.

```js
const predicted = mockForecast(current, source, baselineK, parameters);
const score = id === 'C2' ? current : Math.max(current, predicted);
```

`mockForecast`는 현재 발생 강도가 향후 30분 동안 유지되고 기본 환기가 계속된다는 가정의 계산입니다. 50분에 발생량이 감소한다는 미래 정답을 미리 읽지 않습니다. C1은 환기 OFF를 가정합니다. 화면의 예측값은 ‘팬을 강화하지 않을 경우’의 값이므로 실제 강화 환기 결과와 다를 수 있습니다. 학습된 AI의 정확도를 보여주는 수치가 아닙니다.

C2는 현재 지수가 0.65 이상이면 HIGH로 전환합니다. C3/C4는 현재 또는 예측 지수가 0.65 이상이면 전환합니다. HIGH 이후에는 최소 10분을 유지하고 판단 지수가 0.35 이하가 되어야 BASE로 돌아갑니다. 진입과 해제 기준을 다르게 두는 히스테리시스가 경계값 부근의 반복 켜짐/꺼짐을 줄입니다. 이 수치는 시연값이며 안전 기준이 아닙니다.

## 히트맵과 그래프의 의미

`createScenarioGrid`는 오염원 근처가 높은 고정 공간 분포를 만든 뒤 평균을 기준으로 현재 지수를 배분합니다. 셀 값은 0~1로 잘라 색상에 전달합니다. **방향별 실제 확산이나 센서 위치별 예측을 재현한 결과는 아닙니다.** `DEMO_SOURCE` 위치·퍼짐은 시각적 분포만 바꾸고 전체 농도 동역학은 바꾸지 않습니다.

`HeatmapFloor`는 동일한 평면 864개를 InstancedMesh로 그립니다. `setMatrixAt`은 셀 위치·크기, `setColorAt`은 색을 설정합니다. `needsUpdate`와 `invalidate()`가 GPU 데이터와 화면 갱신을 요청합니다. 반투명 레이어이므로 색상이 바닥색과 섞이며 정확한 팔레트 확인 시 opacity를 1로 바꿀 수 있습니다.

`ScenarioChart`는 네 조건의 전체 120분 합성 결과를 미리 비교합니다. 이 그래프의 미래 결과를 제어기의 입력으로 사용하지 않습니다. 세로선은 현재 재생 시각이고 이벤트 로그에는 그 시각까지 발생한 이벤트만 표시됩니다.

| 조건 | 최초 HIGH | 실내 피크 지수 | 실내 지수 시간적분 | 처리 후 누적 배출 지수 |
| --- | ---: | ---: | ---: | ---: |
| C1 | 없음 | 1.110 | 93.600 | 0.000 |
| C2 | 41분 | 0.651 | 46.849 | 0.720 |
| C3 | 11분 | 0.375 | 37.708 | 0.735 |
| C4 | 11분 | 0.375 | 37.708 | 0.324 |

위 값은 기본 파라미터의 계산 결과이며 실제 농장 성능 증명이 아닙니다. 시간적분은 지수×분으로 상대 비교에만 씁니다. 누적 배출은 환기로 실내에서 제거된 양에 처리율을 적용한 상대량이며 질량 단위가 아닙니다. C1의 배출 0은 실내 축적을 뜻하고, C3의 배출량이 C2보다 큰 것은 실내에서 더 많이 제거했기 때문입니다. 기준 초과 시간은 각 구간 시작값을 이용한 1분 단위 근사입니다.

### C4의 실내 곡선이 C3와 같은 이유

현재 구조는 덕트 → 팬 → 배기 세정기이며 처리 공기가 돈사 내부로 재순환하지 않습니다. 같은 환기 제거계수라면 배출측 세정기를 켜도 실내 제거가 추가되지 않습니다. 따라서 C4에만 임의의 실내 감소 효과를 넣지 않았습니다.

```js
emitted += removed * (scrubberOn ? 1 - p.scrubberEfficiency : 1);
```

이 코드는 환기로 제거된 상대량의 배출측에만 처리율을 적용합니다. 기본 효율 0.7은 가정이며, 세정기가 켜진 구간에만 적용되어 전체 누적량이 정확히 70% 감소하는 것은 아닙니다. 외부 확산·민가 영향은 계산하지 않습니다. 압력손실에 따른 풍량 변화도 현재 모델에 없습니다.

## 직접 변경할 변수

`src/config.js`의 `SIMULATION`을 수정합니다.

| 변수 | 기본값 | 변경 효과 |
| --- | ---: | --- |
| durationMinutes / stepMinutes | 120 / 1 | 전체 길이 / 제어 판단 간격 |
| initialIndex | 0.15 | 공통 시작 지수 |
| sourceStart / sourceEnd | 10 / 50 | 고발생 시작·종료 시각 |
| backgroundSource / activeSource | 0.003 / 0.018 | 기본·고발생 입력 강도 |
| baseRemovalRate / highRemovalRate | 0.006 / 0.045 | 기본·강화 환기의 실내 제거 효과 |
| basePwm / highPwm / maxRpm | 30 / 85 / 1800 | 장치 상태 표시와 회전 애니메이션 |
| triggerIndex / releaseIndex | 0.65 / 0.35 | HIGH 진입 / 해제 기준 |
| minimumHoldMinutes | 10 | HIGH 최소 유지시간 |
| forecastHorizon | 30 | 모의 예측 시간 간격 |
| scrubberEfficiency | 0.7 | C4 가동 구간의 배출측 처리율, 0~1 |
| defaultPlaybackSpeed | 2 | 실제 1초당 모의 분, 화면 선택값 1/2/5/10 중 지정 |

PWM과 RPM은 표시용 비례 관계이고 제거계수와 자동 연동되지 않습니다. 팬 성능 실험에서는 PWM 표시와 제거계수를 함께 설정해야 합니다. 실제로는 풍량–회전수–정압 특성 및 돈사 부피를 연결해야 합니다. 해제 기준은 진입 기준보다 작아야 하며 기간·발생원 전환 시각은 stepMinutes의 정수 배수로 설정하세요. 비음수 발생량·초기 지수, HIGH 제거계수 > 0을 사용합니다.

돈사 크기는 `BARN.width/length/height`, 장치 위치는 `DEVICE_POSITIONS`, 카메라는 `VIEW`, 히트맵은 `HEATMAP.colors/gamma/opacity`입니다. 구조 변수의 자세한 설명과 장치 이동 시 덕트 연결 주의점은 README에 있습니다.

## 재생 속도와 계산 속도를 구분하기

재생기는 `performance.now()`의 실제 경과 시간에 재생 배율을 곱해 선택 시각만 전진시킵니다. 10배속으로 봐도 미리 계산한 결과와 피크는 달라지지 않습니다. 탭이 숨겨지면 재생을 멈춰 복귀 시 시간이 갑자기 건너뛰는 것을 줄였습니다. 제어 계산 간격을 바꾸려면 재생 배율이 아니라 stepMinutes를 바꿉니다.

## 검증 및 다음 연결 지점

```powershell
npm.cmd test
npm.cmd run build
```

test는 동일 입력, 사후/선제 전환 시점, C3/C4 실내 동일성, 최소 유지시간, 수지식, 시간 조회·입력 검증, 히트맵 포화를 6개 테스트로 확인합니다. build는 배포용 정적 파일을 생성합니다. 별도로 브라우저에서 재생·정지·되감기·초기화·배속·3D 토글과 모바일 가로 넘침을 확인했습니다. 큰 번들에 대한 빌드 경고는 남아 있습니다.

다음 단계에서 FastAPI의 현재값·예측값·격자·타임스탬프를 받는 어댑터를 추가합니다. 서버값과 합성 재생 데이터를 명확히 구분하고, 값의 단위·정규화 기준·좌표·예측 시점·결측·오래된 데이터 처리를 먼저 맞춰야 합니다. 이후 mockForecast를 실제 모델 출력으로 교체하고, 공간 예측이 있는 경우 createScenarioGrid 대신 서버 격자를 전달합니다. 현재 코드만으로 실측 디지털 트윈이나 AI 성능 검증이 완성된 것은 아닙니다.
