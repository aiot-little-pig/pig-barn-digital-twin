# 고도화 1단계 보고 — 예측모델 교체 기반

2026.10.11 · 상태: 완료

**시뮬레이터가 예측값을 받는 공통 연결 규격을 만들었다.** 앞으로 모델이 달라져도 화면 쪽에서는 같은 형식의 값을 받도록 백엔드를 분리했다. 실제 AI 모델은 아직 연결하지 않았다.

## 무엇이 달라졌나

| 구현 | 쉬운 설명 |
| --- | --- |
| 공통 요청·응답 규격 | 어느 농장의 어느 시각을 예측했는지, 값의 단위·모델 버전·예측구간이 무엇인지 함께 전달한다. |
| Mock Predictor | 현재 NH₃를 30분 후 예측값으로 유지하는 연결 점검용 모듈이다. 학습 AI가 아니며 가짜 신뢰구간을 만들지 않는다. |
| File Predictor | 미리 저장한 모델 결과를 농장·시각·모델 조건에 맞춰 읽는다. |
| HTTP Predictor | 실제 모델 API에 요청하고 공통 규격에 맞는 응답인지 검사한다. |
| 관측 데이터 로더 | JSON/CSV를 읽고 시간순으로 정리한다. 예측 기준 시각 이후 관측은 입력에서 제외한다. |
| 새 예측 API | `POST /api/v2/predict`를 추가했다. 기존 C1~C4 API와 화면은 유지한다. |

예를 들어 합성 예시에서 **00:10 현재 NH₃가 12 ppm**이면 Mock은 **00:40 예측을 12 ppm**으로 반환한다. 관측 파일에 들어 있는 00:40 값 18은 예측 입력에 들어가지 않는다. 현재값이 없으면 ‘입력 부족’, 서버 연결이 실패하면 ‘연결 실패’를 반환한다.

## 확인한 결과

**총 30개 테스트 통과: Python 15개(기존 4 + 신규 11), JavaScript 15개.**

- 실제 로컬 HTTP 테스트 서버를 띄워 Mock → HTTP 교체 후 같은 요청·응답 규격으로 동작함을 확인했다.
- 미래 관측 입력, 중복 시각, 잘못된 단위/농장 응답, 뒤집힌 예측구간을 차단했다.
- 결측·타임아웃·실패를 확인했고, 오류를 합성값으로 자동 대체하지 않았다.
- 기존 C1~C4 제어와 합성 API, 기존 예측 파일 처리 테스트가 통과했다.

초기 테스트 환경의 임시 폴더/로컬 소켓 제한을 해결한 뒤 위 검증을 완료했다. 테스트용 HTTP 서버는 종료했으며 공개 링크는 만들지 않았다.

## 직접 확인·변경할 것

[연결 안내](../../backend/PREDICTOR_GUIDE.md)에 서버 실행과 API 호출 명령을 정리했다. [예측 요청 예시](../../examples/prediction-request-SYNTHETIC.json)를 Swagger 또는 PowerShell로 호출할 수 있다.

| 설정 | 용도 |
| --- | --- |
| `PREDICTOR_MODE` | `mock`, `file`, `http` 선택 |
| `PREDICTOR_FILE` | 저장 예측 파일 경로 |
| `PREDICTOR_URL` | 실제 모델 API 주소 |
| `PREDICTOR_TIMEOUT_SECONDS` | API 응답 대기 시간, 기본 5초 |

실제 API 규격이 다르면 백엔드 HTTP 어댑터에서 매핑한다. 모델 입력 변수·전처리·입력 창 길이는 모델 담당자의 명세를 받아 연결한다.

## 다음 단계

**2단계: 실제 시간 기준 Replay.** 관측 시각에 맞춰 재생·정지·배속·시간 이동을 처리하고, t에서 발행한 예측과 t+30 실제값을 해당 시각에 도달한 뒤 비교한다. 현재 React 화면은 새 예측 API에 아직 연결하지 않았으며, 센서·히트맵과의 통합은 3단계다.
