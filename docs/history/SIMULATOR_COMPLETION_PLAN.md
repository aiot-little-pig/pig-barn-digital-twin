## 2. 완성 화면과 역할

화면 상단에서 **농장 → 관측 대상 → 모델 조건 → 재생 시각**을 선택한다. 3D 센서 표식과 정보 패널에 현재 NH₃, +30분 예측값, 예측구간, 위험등급을 같은 단위와 기준 시각으로 표시한다. 하단에는 시계열과 재생 조작, 농장별 모델 비교를 둔다.

| 모드 | 보여 줄 내용 | 값의 의미 |
| --- | --- | --- |
| 예측 Replay — 주 화면 | 과거 관측을 시간순으로 공급하고 예측을 발행. 30분 뒤 당시 예측과 실제값 비교 | 실제 관측 또는 명시된 합성 입력 + 선택한 Predictor 출력 |
| 사후 평가 | 전체 평가 구간의 모델 조건·예측구간 비교 | 미래 정답을 포함하는 오프라인 평가임을 표시 |
| C1~C4 가상 제어 | 같은 발생원에서 제어 시점과 장치 상태 비교 | 합성 환경 반응이며 실농장 제어 효과를 입증하지 않음 |

관측 출처와 예측 출처를 별도로 표시한다. 예를 들어 실제 관측 + Mock 예측도 가능하지만 학습 AI 결과로 표시하지 않는다. 가상 팬 조작으로 과거 관측값을 수정하지 않는다.

## 3. 개발 구조와 연결 계약

```text
JSON/CSV → 관측 데이터 어댑터 → 시간순 저장소 → ReplayClock(t)
                                               │ t 이하 이력만 전달
                                               ▼
                                  Predictor 공통 인터페이스
                                  ├─ MockPredictor
                                  ├─ FilePredictor(저장된 모델 출력)
                                  └─ HttpPredictor(실제 모델 API)
                                               │
                                 표준 예측 응답 + 시점별 예측 기록
                                               ▼
FastAPI → 프론트 공통 화면 상태 → 센서 표식·정보 패널·히트맵·그래프

관측 저장소 → t에 도달한 실제값만 대조 → 오차·구간 포함 여부
```

현재 `backend/app.py`의 합성 공급 함수에서 새 계약과 공급 모듈을 분리한다. 프론트는 모델별 응답을 직접 해석하지 않는다. 기존 v1 합성 경로와 `replay-1` 파일은 호환 어댑터로 유지한다.

| 계약 | 필수 내용 |
| --- | --- |
| 데이터 메타정보 | 스키마/데이터 버전, 데이터셋·농장·관측 대상 ID, 관측 출처, 단위, 시간대, 표본 간격, 평가 구간 |
| 관측 | 관측 시각, NH₃와 가용 입력 변수, 값별 결측 상태. 미제공 변수는 생성하지 않음 |
| 예측 요청 | 요청 ID, 농장/대상/모델 조건, 기준 시각 t, horizon=30분, t 이하의 입력 이력 |
| 예측 응답 | 요청 ID, 모델 ID/버전·출처, 기준 시각·대상 시각, 단위, 점예측, 선택적 하한/상한·목표 포함률·구간 산출법, 성공/입력부족/실패 상태 |
| 센서 배치 | sensor ID와 관측 대상 매핑, 표시 좌표, 위치 근거(확인/가정), 관측 범위(센서/돈방/농장) |
| 표시 설정 | 단위별 색상 범위·위험 경계값·근거, 공간 표현 방식, 재생 배속. 모델 입력 정규화와 분리 |

모든 시각은 시간대를 포함한다. 과거 관측 시각·예측 기준 시각과 현재 통신 응답 시각을 분리하여, 오래된 역사 데이터 자체를 통신 장애로 판정하지 않는다. 결측은 null로 유지하고, 단위 불일치·중복·구간 역전·대상 시각 불일치는 명시적으로 거부한다. 원본 예측/구간은 색상 표시를 위해 잘라 저장하지 않는다.

`MockPredictor`는 기본적으로 최신 유효값 유지 방식으로 연결 흐름을 검증하고 미래 정답을 읽지 않는다. 입력이 부족하면 예측 불가를 반환한다. 구간은 기본 미제공이며, 구간 UI 검증에는 별도의 **합성 테스트 구간**을 사용한다. 임의 구간을 보정된 신뢰도로 표현하지 않는다.

실제 모델이 공통 계약을 제공하면 주소·모델 선택 설정만 바꾼다. 다른 규격이면 `HttpPredictor`의 입출력 매핑만 수정한다. 인증정보와 타임아웃 설정은 백엔드에 둔다. 입력 창 길이·변수·전처리는 모델 명세로 관리하며, 임의 API가 아무 수정 없이 연결된다고 가정하지 않는다.

**Replay의 세부 기준**

- 예측 키는 데이터 버전·농장·대상·모델 버전·기준 시각·horizon·설정으로 구성한다. 발행한 예측은 나중 실제값을 보고 덮어쓰지 않는다.
- t+30 정답이 도착하면 그 대상 시각을 예측했던 기록과 대조한다. 대상 시각에 관측이 없으면 미평가로 남긴다. 가까운 값을 임의로 정답에 대입하지 않는다.
- 시간 이동은 재생을 정지하고 선택 시점의 공개 범위를 다시 계산한다. 더 미래 시점에서 얻은 정답·지표가 앞 시점에 남지 않는다.
- 이력 결측·간격 불일치·입력 창 부족은 모델 호출 전 확인한다. 리샘플링이 필요하면 모델 담당 규칙을 적용하며 미래값을 이용한 보간은 하지 않는다.
- 파일 기반 사후 평가는 그대로 지원한다. 실시간처럼 보이는 Replay와 사후 평가의 정답 공개 규칙을 혼용하지 않는다.

**3D·히트맵의 세부 기준**

- 확인된 위치가 있으면 해당 센서 값만 위치에 연결한다. 위치가 없으면 ‘배치 가정’으로 표시한다. 농장 평균 한 값을 여러 센서의 실측값처럼 복제하지 않는다.
- 공간 자료가 없으면 농장 전체 위험도를 균일한 바닥 색으로 표시하고 ‘전체 지표의 시각화’라고 적는다. 합성 모드의 가정된 분포와 구분한다. 공간 보간·확산 계산은 필수 범위에 넣지 않는다.
- 위험등급은 설정된 경계값과 점예측에서 산출하고, 구간이 경계를 걸치면 별도로 표시한다. 구간만으로 ‘위험 확률’을 만들어내지 않는다.
- 실제 ppm 기준이 미정이어도 수치·구간 표시는 동작한다. 위험등급은 ‘기준 미설정’으로 두고, 합성 시연 기준은 명확한 예시 표시와 함께 사용한다. 현재 상대지수 0.65를 ppm 기준으로 옮기지 않는다.
- 값·등급은 문구로도 표시한다. 결측 회색과 낮은 위험 파랑을 구별하고, 색상 범례에 단위·범위·현재/예측을 표시한다.

**C1~C4는 기존 정정안을 유지한다.** C1은 환기 OFF 스트레스 조건, C2는 현재값 기준 사후 강화, C3는 +30분 예측 기반 선제 강화, C4는 C3+배출측 스크러버다. C2~C4는 기본 환기를 유지한다. 실내 재순환이 없는 현재 구조에서 C4가 C3보다 실내 농도를 더 낮춘다고 설정하지 않는다. Replay에서 계산하는 제어 제안은 가상 판단이며 실제 팬 작동 기록과 구별한다.

## 5. 외부 입력이 필요한 부분과 선행 작업

| 나중에 받을 내용 | 지금 완료할 수 있는 준비 | 받은 뒤 필요한 작업 |
| --- | --- | --- |
| 데이터 파일·출처·농장 식별·단위·시간대 | 표준 JSON/CSV 형식, 필드 매핑 설정, 결측 검사와 합성 fixture | 원본 컬럼 매핑과 출처 확인. 독립 농장 근거가 없으면 다중 농장 실증으로 표시하지 않음 |
| 모델 입력 변수·창 길이·샘플 간격·전처리·API 예시 | Predictor 인터페이스, HTTP 모의 서버와 계약 테스트 | 공급자 어댑터/설정 연결, 정상·누락 요청 대조 |
| 전이 조건별 출력·평가 구간·모델 버전 | 조건 비교 UI와 공통 표본 계산 | 실제 조건 이름·평가 범위 등록, 담당자 지표와 대조 |
| 구간 하한/상한·목표 포함률·산출법 | 구간 유무 모두 처리하는 화면·테스트 | 실제 구간 표시·포함률 계산. 미제공이면 점예측만 사용 |
| 센서 위치·대표 범위, ppm 위험 기준 | 배치/위험 설정 파일과 미확정 상태 처리 | 근거 있는 설정값 입력. 새 하드웨어 실측을 요구하지 않음 |

메일 회신이나 자료 수령 사실만으로 데이터가 코드에 연결되었다고 판단하지 않는다. 데이터 확보·모델 학습·제안서 집필은 이 개발 계획의 작업으로 넘겨받지 않는다. 실제 모델 연결 후 성능 검증까지 ‘이미 완료’라고 부르지 않는다.

## 7. 최종 인수 기준

아래 항목을 모두 통과하면 **시뮬레이터 구현 완료·실제 모델 연결 대기**로 판정한다.

- [x] Mock으로 농장·대상·조건 선택부터 현재값 → 30분 예측 → 구간 → 위험표시 → 정답 비교까지 실행된다.
- [x] 표준 계약의 테스트 HTTP Predictor로 교체해도 프론트 수정 없이 같은 흐름이 동작한다.
- [x] 미래 관측이 예측 입력에 들어가지 않고, 기준/대상 시각·단위·조건이 모든 화면에서 일치한다.
- [x] 농장/센서 전환, 불규칙 시간 간격, 정답 결측, 구간 미제공, 서버 오류, 늦게 도착한 응답을 검증한다.
- [x] 농장별 공통 평가 표본과 유효 건수를 표시하며, 사전에 계산한 작은 검증 예제와 지표가 일치한다.
- [x] C1~C4 기존 제어 검증을 통과하고, 합성 결과·역사 관측·모델 예측·가상 장치 상태를 구분한다.
- [x] 새 프로세스에서 시작·종료·재시작과 별도 폴더 추출본 실행을 검증했고, 실행·설정·모델 연결 안내를 제공한다. OS 재부팅 및 새 PC 의존성 설치는 별도 확인 대상이다.

이 판정은 실제 농장과 보정된 물리 디지털트윈 완성이나 학습모델 성능 입증을 뜻하지 않는다. 이번 완성 범위는 **관측·예측을 재생하고 가상 제어를 설명하는 돈사 내부 디지털트윈 시제품**이다.
