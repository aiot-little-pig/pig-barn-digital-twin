# 다중 농장 전이학습·예측 신뢰도 — 오프라인 검증과 시뮬레이터 계획

상태: 제안서·팀 회의용 설계 초안. 핵심 방향은 사용자 지시로 확정, 데이터·모델·구간 산출법·수치 목표는 미확정. 학습과 성능 검증을 실행한 결과 문서가 아닙니다.

## 1. 무엇을 연구 성과로 볼 것인가

질문은 두 가지입니다.

1. 여러 소스 농장에서 학습한 모델을 새 타깃 농장에 적용할 때, 소량의 타깃 데이터로 적응하면 예측 오차가 개선되는가?
2. 점예측뿐 아니라 예측구간을 제공할 때, 실제값의 포함률과 구간 폭은 농장별로 어떠한가?

이를 기존에 수집된 농장 데이터로 검증하고 시뮬레이터로 재생합니다. 신규 하드웨어 실측이나 실물 팬 구동을 성공 조건으로 두지 않습니다. 다만 **팀이 새로 측정하지 않는 것**과 **실제 관측 데이터가 없어도 실증할 수 있다는 것**은 다릅니다. 합성 데이터만 있다면 구현 흐름은 확인할 수 있지만 실제 농장 일반화 성능을 입증할 수는 없습니다.

## 2. 회의 전 준비할 범위

이번에 준비한 것은 제안서 문장, 연구·시연의 구분, 데이터 목록 양식, 평가 분할안, 재생 응답 필드 초안입니다. 데이터 없이 농장 수·성능 목표·예측구간 수치나 알고리즘을 확정하지 않습니다. 임의의 ‘예측값 ±10%’를 만들어 신뢰도 기능 완성으로 표시하지 않습니다.

## 3. 농장 데이터 목록 양식

| 데이터 식별자 | 농장 수/식별 근거 | 기간·간격 | NH₃ 실제값·단위 | 공통 입력 변수 | 환기 이력 | 사용 조건 | 확보 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 후보 1 | 확인 필요 | 확인 필요 | 확인 필요 | 확인 필요 | 확인 필요 | 확인 필요 | 미확정 |
| 후보 2 | 확인 필요 | 확인 필요 | 확인 필요 | 확인 필요 | 확인 필요 | 확인 필요 | 미확정 |

파일 개수나 챔버 수를 농장 수로 세지 않습니다. 같은 농장의 기간 분할은 시간에 따른 변화 검증이며 독립 농장 전이 검증과 구분합니다. 입력 변수·단위·시간 간격을 맞추고 보간·결측 처리 방식도 기록합니다. 비전 정보는 시간·대상이 연결될 때만 선택적으로 추가합니다.

## 4. 평가 분할 초안

농장 식별과 충분한 기간이 확보된 경우 다음 절차를 적용하는 안입니다.

1. 소스 농장과 타깃 농장을 분리합니다. 타깃 평가 데이터는 소스 학습에 포함하지 않습니다.
2. 타깃 농장 시계열을 시간 순서대로 초기 적응 구간, 예측구간 보정 구간, 최종 평가 구간으로 나눕니다. 길이·비율은 데이터 확인 후 정합니다.
3. 입력 창이나 예측 대상 시각이 분할 경계를 넘어 미래 정보를 가져오지 않도록 샘플을 구성합니다. 스케일링·변수 선택·모델 선택에 최종 평가 구간을 사용하지 않습니다.
4. 타깃 농장을 바꿔 평가할 수 있으면 농장별 결과를 보고합니다. 가능한 농장 수가 적으면 제한을 그대로 명시합니다.

여기서 소량 적응 데이터는 타깃 농장의 기존 기록 일부입니다. 시연 중 새로 센서를 설치해 수집할 필요는 없습니다. 예측구간 방법을 선택할 때는 시계열 의존성과 농장 간 분포 차이를 고려하며, 명목 포함률이 새 농장에서 자동 보장된다고 가정하지 않습니다.

## 5. 비교군 초안

| 비교군 | 목적 | 맞춰야 하는 조건 |
| --- | --- | --- |
| Persistence | 최신 관측 NH₃ 값을 +30분 예측으로 유지하는 기준선 | 같은 기준 시각과 실제값 |
| 소스 학습 모델, 타깃 적응 없음 | 새 농장에 바로 적용한 성능 | 동일한 타깃 평가 구간 |
| 타깃 초기 데이터만으로 학습 | 전이 없이 소량 데이터로 학습한 성능 | 전이 모델과 같은 적응 데이터 양 |
| 소스 학습 후 타깃 적응 | 전이의 추가 효과 | 동일 평가 구간·입력·적응 예산 |

점예측의 ‘타깃 적응 없음’과 타깃 라벨을 사용한 구간 보정은 구분해서 기록합니다. 타깃 데이터를 구간 보정에 사용했다면 시스템 전체가 타깃 데이터 없이 동작했다고 부르지 않습니다. 복잡한 모델 이름을 먼저 확정하지 않고 확보 데이터로 수행 가능한 비교부터 정합니다.

## 6. 예측 신뢰도의 표시와 평가

- **점예측:** 기준 시각 t에서 t+30분의 NH₃ 예측값.
- **예측구간:** 같은 대상 시각의 하한·상한과 목표 포함률. 평균 추정의 신뢰구간과 혼동하지 않습니다.
- **관측 포함률:** 평가 구간에서 실제값이 하한과 상한 사이에 들어온 건수 / 유효 평가 건수.
- **평균 구간 폭:** 유효 평가 건의 (상한−하한) 평균. 관측값과 같은 단위로 표시합니다.
- **농장별 결과:** 전체 평균뿐 아니라 농장별 오차·포함률·폭·표본 수를 함께 제시합니다.

목표 포함률 90%를 선택하더라도 화면에 ‘이 예측의 정확도 90%’라고 표시하지 않습니다. 목표값과 실제 평가 결과는 다릅니다. 값이 누락되면 해당 지표의 분모에서 어떻게 제외했는지 기록합니다.

화면의 통신 신선도와 모델 신뢰도도 다릅니다. 최신 응답이 도착했다는 사실은 모델의 오차가 작거나 예측구간이 적절하다는 증거가 아닙니다.

## 7. 시뮬레이터의 역할을 두 가지로 구분

**예측 검증 재생:** 기존 타깃 농장 기록의 현재값, +30분 예측값, 예측구간을 재생하고 대상 시각의 실제값과 비교합니다. 농장·모델·전이 전후 조건을 선택하는 화면을 후속 개발합니다. 이 경로에서는 가상의 팬 조작으로 과거 실제 관측값을 바꾸지 않습니다.

**가상 제어 시연:** 기존 C1~C4 합성 환경 모델로 환기 판단과 장치 상태 변화를 보여줍니다. 제어 결과는 설정한 발생량·제거계수에 따른 모의 결과입니다. 실제 관측 데이터를 이용한 예측 성능과 합산하거나 실농장 저감률로 제시하지 않습니다.

현재 앱은 두 번째 경로와 합성 데이터 API까지만 구현되어 있습니다. 첫 번째 경로의 실데이터 재생·예측구간·전이 전후 비교 UI는 아직 구현하지 않았습니다.

## 8. 모델 담당자와 맞출 최소 출력 초안

| 필드 묶음 | 필요한 내용 |
| --- | --- |
| 식별 | 데이터셋 ID, 농장 ID, 모델 버전, 전이 전/후 조건 |
| 재생 시각 | 과거 관측 기준 시각, +30분 예측 대상 시각 |
| 전송 시각 | 서버 응답 생성 시각, 파일/실험 버전 |
| 값 | 현재 관측값, 점예측, 단위 |
| 구간 | 하한, 상한, 목표 포함률, 구간 산출·보정 방법 식별자 |
| 정답 | 대상 시각의 실제 관측값. 모델·제어기 입력과 분리 |
| 평가 정보 | 평가 농장·기간·유효 건수, MAE/RMSE, 포함률·평균 폭 |
| 품질 | 결측·구간 미제공·출처, 실측 기록과 합성 결과 구분 |

**현재 API의 오래된 데이터 판정은 재생 모드에 맞춰 개정해야 합니다.** 과거 기록의 관측 시각을 현재 시각으로 덮어쓰면 안 됩니다. 역사적 데이터의 시각과 전송 상태를 분리하고, 파일 재생에서는 벽시계 기준 10초 규칙을 관측값에 적용하지 않습니다. 재생 위치·샘플 간격·결측과 응답 연결 상태를 각각 검증하도록 다음 API 버전에서 설계합니다. 아직 코드에는 적용하지 않았습니다.

실제값은 평가에서만 사용합니다. 순차 시연에서는 재생 시계가 예측 대상 시각에 도달했을 때 정답을 공개하고, 사후 비교 화면이라면 전체 기록을 보여주는 평가 모드임을 표시합니다.

## 9. 회의에서 남은 선택

1. 실제 확보된 독립 농장과 기간, 입력 변수는 무엇인가?
2. 타깃 초기 적응·구간 보정·최종 평가에 사용할 기간은 무엇인가?
3. 예측구간 산출법과 목표 포함률은 무엇이며 누가 결과를 제공하는가?
4. 시뮬레이터에 넘길 파일 예시와 단위는 무엇인가?
5. 보조 C1~C4 시연에서 사용할 제어 기준과 C4의 역할은 무엇인가?

위 사항이 정해지면 실제 예측 파일 어댑터 → 예측구간·전이 전후 재생 화면 → 결과 저장 순으로 구현합니다. 신규 센서 수집, 물리 장치 통신, 현장 시운전을 선행 조건으로 두지 않습니다.
